## 1 데이터 전처리 및 회수율 예측 Model1 연계

### 프로젝트 담당 및 역할

Module 1은 RAW·CLEAN 구분과 결측치·이상치·파생변수·품질 검증을 담당합니다. Model1 회수율 예측은 Module 2 연계 선행 실험으로 구분합니다. 전처리·모델 담당자의 이름은 제공 자료에서 확인되는 범위를 넘어 지정하지 않습니다.

### 현재까지 진행사항

#### 원료 성분 대치

Ni·Co·Li·Mn 함량과 Cu·Fe·Al 불순물 등 7개 변수를 대상으로 원료등급별 평균·중앙값 대치를 비교했습니다. 배치ID 순서로 Train/Validation/Test를 70/15/15로 분할하고, 통계는 Train에서만 계산했습니다. 등급·성분별 관측값이 5개 미만이면 전체 Train 통계를 사용했습니다.

Validation 완전행 41개에서 행마다 성분 1개를 무작위로 가렸습니다. 초기 20% 표본 약 8개 셀에서 완전행 100%로 확대한 뒤 시드 42~46의 5회 실험을 30회까지 늘렸습니다.

| 5회 통합 지표 | 평균 대치 | 중앙값 대치 |
| --- | ---: | ---: |
| MAE | 0.8356 | 0.8348 |
| RMSE | 1.2077 | 1.2071 |
| 실제값에 더 가까운 횟수 | 98 | 107 |

30회에서도 두 방법은 유사했습니다. 성능 차이가 작고 극단값에 상대적으로 강건하다는 이유로 중앙값을 선택했습니다. 같은 Validation 배치를 반복했으므로 누적 검사 횟수는 독립 표본 수가 아닙니다.

평균·중앙값 대치 Excel을 생성하면서 원본 CLEAN의 행·열 순서와 측정값을 보존하고 대치 셀을 노란색으로 표시했습니다. 원료 성분 211개 대치 셀은 관측 범위 안에 있었으나, 통계 계산에 사용한 분포와 다시 비교한 순환적 검사이므로 복원 정확도의 증거로 삼지 않았습니다.

#### 공정 조건 대치와 품질 검증

전체 Train 중앙값과 등급별 Train 중앙값을 30회 비교했으며 전체 중앙값이 세 변수에서 근소하게 우세했습니다.

| 변수 | 결측 수 | 최종 대치값 |
| --- | ---: | --- |
| 원료투입량 | 0 | 해당 없음 |
| 황산투입량 | 2 | 전체 Train 중앙값 930.5 L |
| 침출온도 | 40 | 전체 Train 중앙값 67.7 °C |
| 침출시간 | 38 | 전체 Train 중앙값 4.09 hr |
| 합계 | 80 | |

| 황산투입량 대치 후보 | MAE (L) | RMSE (L) |
| --- | ---: | ---: |
| 전체 중앙값 | 256.15 | 311.39 |
| 황산/원료비 기반 | 359.89 | 438.21 |
| 유사 배치 KNN | 304.31 | 352.80 |

| 변수 | 전체 중앙값 MAE | 등급별 중앙값 MAE | KNN MAE |
| --- | ---: | ---: | ---: |
| 침출온도 (°C) | 14.36 | 14.64 | 14.92 |
| 침출시간 (hr) | 1.632 | 1.671 | 1.747 |

KNN은 비교 후보였으며 최종 채택 방법이 아닙니다. 등급별 IQR 이상치 후보는 0건이었으나 물리적 정상 범위 판정과 구별했습니다.

`clean_final_process_imputed.xlsx`에 CLEAN 420행×24열과 대치로그·대치요약을 생성했고, 황산/원료비와 온도시간 지표를 재계산했습니다. 기본 품질 검증에서 당시 25개 항목이 PASS였고 7개 성분 결측은 0개였습니다. 공정 조건의 모든 결측이나 실제 허용범위까지 검증했다는 의미는 아닙니다. 이후 분석일자 21개 결측을 별도로 확인했습니다.

#### 파생변수 8개

| 파생변수 | 계산식 |
| --- | --- |
| 불순물합계 | Cu + Fe + Al |
| Ni/Co 함량비 | Ni ÷ Co |
| 황산/원료비 | 황산투입량 ÷ 원료투입량 |
| 온도시간 지표 | 침출온도 × 침출시간 |
| Ni 투입량 | 원료투입량 × Ni 함량 ÷ 100 |
| Co 투입량 | 원료투입량 × Co 함량 ÷ 100 |
| 목표금속 투입량 | Ni 투입량 + Co 투입량 |
| 불순물/목표금속비 | 불순물합계 ÷ (Ni 함량 + Co 함량) |

8개 변수의 계산 정합성을 확인했습니다. 최종 대치 근거로 직접 사용하지는 않았으며 황산/원료비 기반 대치만 후보 방법으로 실험했습니다.

#### Model1 비교 실험

Random Forest에서 기본 11개와 파생변수를 포함한 19개 입력을 비교했습니다.

| Test 지표 | 기본 11개 | 파생변수 포함 19개 |
| --- | ---: | ---: |
| Ni R² | 0.7548 | 0.7603 |
| Ni MAE | 2.1516 | 2.1694 |
| Co R² | 0.7755 | 0.7930 |
| Co MAE | 2.6329 | 2.4913 |

Ni는 지표별 결과가 엇갈렸고 Co는 개선됐습니다. 8개 전체가 반드시 유리하다고 판단하지 않았습니다. 개별 추가의 Validation 비교에서는 황산/원료비가 가장 일관된 개선을 보여 조합 비교로 이어졌습니다.

| 모델 | 구성 | Ni Validation MAE | Co Validation MAE |
| --- | --- | ---: | ---: |
| A | 기본 11개 | 2.1433 | 2.8102 |
| B | A + 황산/원료비 | 2.1139 | 2.6424 |
| C | B + 불순물합계 | 2.1727 | 2.6454 |
| D | C + 불순물/목표금속비 | 2.1778 | 2.6699 |

B 12개 입력을 유력 후보로 선택했습니다. **Train+Validation 재학습 후** Test R²는 Ni 0.7866, Co 0.8062였으며 최종 확정 결과는 아닙니다.

별도 과적합 진단은 모델 B의 Train·Validation·Test를 **동일 학습 모델**로 비교한 결과입니다. 설정은 `n_estimators=200`, `max_depth=10`, `min_samples_leaf=3`, `random_state=42`입니다.

| 금속 및 구간 | R² | MAE | RMSE |
| --- | ---: | ---: | ---: |
| Ni Train | 0.9405 | 1.1085 | 1.4787 |
| Ni Validation | 0.7629 | 2.1139 | 2.6910 |
| Ni Test | 0.7680 | 2.0816 | 2.6607 |
| Co Train | 0.9376 | 1.2964 | 1.7219 |
| Co Validation | 0.7482 | 2.6424 | 3.3536 |
| Co Test | 0.8004 | 2.4281 | 2.9985 |

Train과 Validation R² 차이는 Ni 약 0.178, Co 약 0.189로 과적합 징후가 있습니다. Validation·Test 성능이 완전히 붕괴한 것은 아닙니다. Ni Validation MAE는 학습 88행일 때 약 2.477에서 294행일 때 약 2.114로 감소했습니다.

- RAW 데이터사전 기준 최종 이상치 처리 검증, 분석일자 결측 처리 방침, 최종 전처리 전체 정규화·표준화는 미완료입니다.
- Model1 과적합 개선과 최종 모델 확정은 미완료입니다. XGBoost·LightGBM·SHAP 완료 및 최적화 완료는 확인되지 않았습니다.
- 실제 수행한 코드와 산출물을 저장소에 통합하고 재현 절차를 추가해야 합니다.

### 멘토링 사전질문

1. **결측 대치 방법 결정:** 완전행 41개를 마스킹한 복원 실험과 30회 반복 결과를 근거로 중앙값을 선택했습니다. 완전행에 임의의 빈칸을 만들어 평균값·중앙값으로 복원하고 원래 값과 비교한 결과로, 실제 결측값의 대치 방법을 결정해도 될까요?
2. **파생변수 탐색:** 8개 전체 추가와 변수 중요도를 참고한 추가가 일관된 성능 개선으로 이어지지 않았습니다. 파생변수는 많이 만들 수 있지만 개선이 작을 때, 좋은 파생변수를 찾으려면 많은 실험을 반복하는 방법밖에 없을까요?
3. **과적합 원인 진단:** 위 정량 진단은 모델 B 기준입니다. 파생변수가 없는 기본 모델 A까지 살펴볼 때, 과적합 위험이 어디서 생기는지 어떻게 진단하면 좋을까요?
4. **새 데이터 예측:** 모델 후보 선정과 과적합 진단까지만 수행했습니다. 새로운 데이터에 대한 예측 오차율을 낮추려면 어떤 방법을 적용하는 것이 좋을까요?

## 2 디지털 트윈 웹과 서버

### 프로젝트 담당 및 역할

한림대학교 콘텐츠IT학과 3학년 김용준이 React/TypeScript 사용자 화면과 FastAPI 중계 서버를 개발하고 있습니다.

### 현재까지 진행사항

- 원료 이름, Ni/Co 함량, 투입량, 황산량, 침출 온도·시간 입력 화면 구현.
- 현재·추천 조건을 나란히 표시하고 예상 회수율을 표·그래프로 비교. 미입력 숫자는 null로 전달하고 서버에서 임의 보정하지 않음.
- 추천값 반영·수정, 변경 시 재분석, 최종 조건 확정과 적용 요청 흐름 구현.
- Unity 명령 조회·실행 상태 보고 구조, 대기·실행 중 추가 적용 제한, 이전 상태 덮어쓰기 방지, 상태 조회 재시도 구현.
- 모의 데이터와 Unity 대역 스크립트로 입력부터 적용 요청, 실행 중·완료 상태의 화면 반영까지 확인.
- 노트북·태블릿 기본 조작 확인. 좁은 화면의 비교표는 가로 스크롤 발생.

### 직면한 문제와 미완료 사항

실제 AI 모델과 Unity 프로젝트는 아직 연결하지 않았습니다. 실제 소스도 이 저장소에 통합하지 않았습니다. 조건 일치 검증은 화면에서만 수행하며, Unity 명령 조회 즉시 서버 큐에서 삭제합니다. 같은 Wi-Fi에서 로그인 없이 분석·시작 요청이 가능합니다. 실제 연동과 명령 재전송·수신 확인·중복 방지 및 인증 적용 범위는 후속 작업입니다.

### 멘토링 사전질문

1. **분석 조건과 실행 조건:** 조건 변경 시 재분석해야 확정하도록 했지만 화면에서만 검사합니다. 서버에도 분석 ID와 당시 입력값을 저장하고 Unity 적용 전에 같은 조건인지 검증하는 것이 좋을까요? 지금 단계에서도 서버 검증까지 필요할까요?
2. **명령 유실과 중복:** 명령 조회 직후 큐에서 삭제하므로 수신 중 연결이 끊기면 유실될 수 있고 재전송하면 중복 실행될 수 있습니다. 수신 확인과 중복 실행 방지는 어떤 순서로 구현하는 것이 좋을까요?
3. **시연 인증과 권한:** 같은 Wi-Fi에서 로그인 없이 요청 가능한 가상 공장 시연입니다. 이런 환경에도 인증이나 조회·제어 권한 구분이 필요할까요? 보안을 적용한다면 무엇부터 챙기는 것이 좋을까요?

## 3 Unity 3D 가상 공장

### 현재까지 진행사항

Unity 6000.0.68f1과 HDRP 17.0.4, Alembic 2.4.7 환경에서 공장·수조·맵을 배치하고 사용자 Play 확인을 마친 시연 체크포인트입니다. `unity/`를 Unity 프로젝트 루트로 사용합니다.

| 씬 | 용도 |
| --- | --- |
| `FactoryDemo` | 기존 공장·수조 배치와 수위 슬라이더 확인 |
| `FactoryDemoProcess` | 기존 Start/Reset 및 부속물 투입·수위 변화 시연 |
| `FactoryDemoProcessSample` | 최신 주입·안정화·투입·교반·배출 시연. 기본 실행 씬 |

- Start 후 상단 물 주입, 수면 안정화 뒤 부속물 투입을 순서대로 표현합니다.
- 교반 속도가 점진적으로 증가하고, 교반 중 물색이 바뀌며 마지막 2초에 조각이 소실됩니다.
- 배출에서도 같은 Alembic 물 표면을 유지합니다. Reset은 수위·색·조각·교반과 상태를 초기 상태로 되돌립니다.
- 최신 씬의 Inspector 값은 주입 4초, 투입 2.5초, 교반 6초, 조각 소실 2초, 배출 5.5초입니다. 소실은 교반의 마지막 구간과 겹칩니다. 수면 안정화 시간은 별도 고정 Inspector 값이 아닌 코드에서 계산합니다.
- `WaterLevelController.cs`와 `FactoryProcessDemoController.cs`, .meta는 검증된 원본 그대로 통합했습니다. 세 씬의 통합용 복사본에서만 Alembic 임시 메시와 해당 MeshFilter 오버라이드를 각각 1개씩 제거했습니다. 그 외 씬 객체·GUID·Inspector 값은 보존했습니다.

### 검증 범위와 미완료 사항

사용자가 원본의 최신 시연 효과를 Play에서 확인했습니다. 통합 시 두 C# 파일을 실제 Unity Core/uGUI/TMP/Alembic/HDRP 참조로 경고를 오류로 처리하여 컴파일하고, 코드·.meta 해시, 씬의 임시 메시 제거 외 변경 없음과 GUID 참조를 검사했습니다. 웹/API/AI 통합 시험이나, 임시 메시를 제거한 씬의 새 체크아웃 Unity 임포트·Play·빌드 시험을 완료한 것은 아닙니다.
